开发记录：AI 周报生成器 ​

每个周五下午我都要花大概四十分钟写周报。真正麻烦的不是写，而是回忆这周到底干了什么——提交记录是 fix: typo，聊天记录是「那个问题好了」，从这些碎片里拼出一份能看的周报，纯粹是体力活。

于是我做了这个工具。这篇文章记录完整的开发过程。

需求收敛 ​

按我的习惯，先写「完成定义」：

输入这周的 Git 提交记录和随手记的笔记，输出一份 300 字左右、按主题归类的周报。

明确不做的事情：

  • ❌ 不做 Web 界面（我自己用的东西，命令行最快）
  • ❌ 不接公司系统（涉及权限，而且每个公司接口都不一样）
  • ❌ 不做多人协作

这三条排除之后，项目从「一个产品」变成了「一个脚本」，一个周末足够。

第一轮：先把数据拿到手 ​

第一版完全不碰 AI，只做一件事：把 Git 提交记录拉出来。

bash
git log --since="7 days ago" --pretty=format:"%h|%an|%ad|%s" --date=short
1

用 Node.js 解析：

js
import { execFileSync } from 'node:child_process'

export function readCommits(since = '7 days ago') {
  const output = execFileSync('git', [
    'log',
    `--since=${since}`,
    '--pretty=format:%h|%an|%ad|%s',
    '--date=short'
  ], { encoding: 'utf-8' })

  return output
    .split('\n')
    .filter(Boolean)
    .map((line) => {
      const [hash, author, date, ...rest] = line.split('|')
      return { hash, author, date, subject: rest.join('|') }
    })
}

用 execFileSync 而不是 execSync

execFileSync 直接传参数数组，不需要拼字符串，也就不会有引号和转义带来的注入问题。

第二轮：过滤噪音 ​

真实的提交记录里大概有一半是噪音：

text
fix: typo
Merge branch 'main'
chore: bump version
wip
1
2
3
4

这些进到 AI 的输入里只会干扰输出。我加了一层规则过滤：

js
const NOISE = [
  /^merge /i,
  /^chore: (bump|release)/i,
  /^(fix: )?typo$/i,
  /^wip$/i
]

function isNoise(subject) {
  const text = subject.trim()
  return text.length < 4 || NOISE.some((rule) => rule.test(text))
}

第三轮：接上模型 ​

提示词我改了很多版，最后固定成这个结构：

js
const prompt = `
你是一个帮我写周报的助手。请把下面的原始记录整理成一份中文周报。

要求：
1. 按主题归类，不要按时间顺序罗列
2. 每条用一句话说清「做了什么」和「结果如何」
3. 合并重复项，忽略无意义的提交
4. 总长度控制在 300 字以内
5. 不要编造记录里没有的信息

提交记录：
${commits.map((c) => `- [${c.date}] ${c.subject}`).join('\n')}

补充笔记：
${notes || '（无）'}
`

踩过的坑 ​

坑一：日期格式不一致 ​

git log --date=short 给的是 2025-01-12，而我的笔记用的是 1/12。第一版直接把它们混在一起给 AI，结果周报里的日期全乱了。

解决办法是在解析阶段统一成 ISO 格式，输出时再格式化：

js
function toISO(text) {
  const date = new Date(text)
  return Number.isNaN(date.getTime()) ? null : date.toISOString().slice(0, 10)
}

坑二：长输入被截断 ​

有一周我提交特别多，加上笔记一共 6000 多个字符，结果后面一半被静默丢弃了。现在我加了长度检查，超过阈值就先让模型做一次摘要，再生成周报。

坑三：周末提交算到下周 ​

我用 --since="7 days ago" 取数据，周一运行的时候会把上周五的提交算进来。改成按周一到周五取：

js
function currentWeekRange() {
  const now = new Date()
  const day = now.getDay() || 7          // 周日算第 7 天
  const monday = new Date(now)
  monday.setDate(now.getDate() - day + 1)
  return { since: monday.toISOString().slice(0, 10) }
}

最终效果 ​

现在我的流程是：

bash
npx weekly-report --notes ./notes.md --out ./weekly.md
1

十几秒后得到一份可以直接粘贴进周报系统的文本。四十分钟变成了两分钟。

如果重做 ​

  • 先做数据清洗，再接模型。我一开始把顺序搞反了，花了不少时间调提示词去处理本该在代码里过滤的噪音。
  • 把提示词当代码管理。现在我把提示词放在单独的文件里，改一次就提交一次，能清楚看到哪次改动让效果变好或变差。
  • 加个缓存。同一个输入没必要重复调用模型，尤其是在调提示词的时候。
